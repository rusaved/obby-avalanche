# Соответствие правилам VK и ОК («Лавина 21», K-04…K-08, K-10, K-13)

Сборка `dist-vk` (`npm run build:vk`, режим vite `vk`), на Pages — https://rusaved.github.io/obby-avalanche/vk/ (собирает `npm run build:pages`, папка `dist-pages/vk/`). Одна сборка на обе площадки: VK или ОК — по параметрам запуска (`vk_client=ok` или `vk_platform=*_ok` → ОК). В обычной вкладке `?mock=vk` включает заглушку моста (`src/platform/vk-mock.ts`) и набор проверки продюсером; подписанный запуск VK/ОК (`vk_app_id` и `sign`) их не включает.

Проверки: `npm run check:vk` (файлы сборки), `tests/platform/vk.test.ts` (unit на заглушке моста), `npm run e2e:vk` (`e2e/vk-k21.spec.ts`, статическая структура `vk/`), ревизоры `docs/evidence/K21/review-usability.md` (3,4) и `docs/evidence/K21/review-moderator.md` (3,75), их «2» починены или за штабом (id групп, Q-K21-2). Сборка Яндекса не меняется: код VK, заглушка и набор проверки в архив Яндекса не попадают (`check-release`, проверка 6).

Перед подачей штабу: заполнить в `content/vk.json` `appId`, `vkGroupId`, `okGroupId` (сейчас 0 — кнопки «Вступить» нет; `npm run check:vk -- --submit` красный, пока пусто). Документы — типовые документы VK, выбранные в панели VK (решение штаба 27.10); своих страниц нет.

| Требование | Как выполнено | Чем проверено |
|---|---|---|
